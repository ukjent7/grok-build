# 计划模式与权限

高风险操作前 Grok 会先问你——复杂任务还可以先规划再动手。

## 权限

Grok 想跑高风险命令或改文件时，会停下来问：允许一次、这类操作以后都允许，还是拒绝。

只读永远免费：读文件、搜索、无害的只读命令（`ls`、`git status`、`grep`……）从不弹窗。链式命令会逐段检查——`ls && rm -rf tmp` 照样会为那个 `rm` 弹窗。

信任这个会话？`/always-approve`（或 `Ctrl+O`）跳过所有确认。

## 计划模式

任务越大、越含糊，越适合**计划模式**：Grok 以只读方式探索代码库，拿出方案，等你批准*之后*才写代码。

- 提示有焦点时按 **`Shift+Tab`** 循环模式：普通 → 计划 → 始终批准。
- **`/plan`** 直接进计划模式；`/plan <task>` 一步到位规划指定任务。

计划 ready 后：`a` 批准，`c` 对某一行评论，`s` 要求改方案——Grok 会跟你迭代到满意再动手。

好习惯：“到底该怎么做？”用计划模式，“就这么干”用普通模式。

## 长时间命令

构建或测试占着轮次不放？**`Ctrl+B`** 把它送到后台——Grok 继续干活，跑完会通知你（`Ctrl+G` 看任务面板）。
